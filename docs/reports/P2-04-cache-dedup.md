## 3. What this does and does not buy

- **Cache:** a repeated prompt costs **$0** and consumes no provider quota. This is measured; it is the cheapest lever and it is already on for every run. Its value at corpus scale depends on re-processing: a paper is processed once (lazy), so the cache primarily protects resumed runs and prompt-identical repeats.
- **Dedup:** the census is a measurement, not a prompt change. Removing duplicate sentences from prompts would change the baseline's evidence and needs its own live separation run plus a quality row; the token estimate above is therefore an **upper bound on avoidable text**, not a claimed saving. Within-paper duplicates (174) are the safer first target because they cannot remove a unique claim.
- Near-duplicate detection is approximate: MinHash/LSH proposes candidates and Jaccard verifies them; a pair can be missed if no band collides. Exact counts are exact.
- The census covers the frozen 100-paper baseline sample (the papers with cached full text), not the whole 4,928-paper corpus. Corpus-wide rates are unknown.

## Limits (repeat in every P2 report)

- This report contains no quality claim: it isolates cache and repetition.
